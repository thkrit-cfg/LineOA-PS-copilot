Staff Inbox — Wireframe Redesign v2

The current “CRM” button opens a global search of every customer — so a staff member chatting with customer A can wander into customer B’s record. Staff never need to browse other customers mid-conversation. This redesign moves CRM context inline into the chat (always about the person on the line) and keeps search only where it belongs: linking an unknown customer. The chat layout follows LINE OA Manager — conversation list on the left, conversation on the right, CRM inspector on the right — so staff don’t relearn the layout.

01

What staff actually need while chatting

A staff member’s job in a thread is one thing: reply fast, personally, correctly. Every CRM feature must serve that moment. Anything that pulls attention to a different customer is a defect, not a feature.

Know who is messaging Name, photo, loyalty tier at a glance Name + photo in header; tier hidden in drawer partly Tier + segment chip in header
Understand the request Intent of last message + suggested reply Intent chip + AI draft keep Unchanged
Personalize the reply Top categories, dietary prefs, recent purchases, staff notes 3 taps deep inside a global search drawer gap 1 tap → inline profile panel (this customer only)
Gauge value & urgency LTV, segment, at-risk signal Dense 2-row strip + value strip partly Single compact strip, tap to expand
Offer the right thing Product recs + the promo type they prefer Recs ✓; preferred promo type buried partly Recs kept + “prefers: …” hint beside them
Verify loyalty The 1 card number (tap to copy) Only inside drawer gap Card on the strip, tap to copy
Link an unknown customer Find CRM record by phone / name / card Link mode works keep Kept — and becomes the only place search exists
Log context for next time Add / edit a staff note Notes are read-only gap Editable note in profile panel
Call the customer Phone number, one tap Copy-only inside drawer gap “Call” action in profile panel
Core finding: the drawer’s global search is right for linking and wrong for viewing. In view mode it invites staff to open another customer’s record (wrong context + PDPA exposure), and its “Set as Active Customer” button does nothing. The fix is structural: profile = inline, search = link-only.

When does search appear?

One decision point, one rule. If the answer is “yes”, staff never sees a search box.

Why this is safe: the profile panel receives the customer from the thread record (/api/inbox/threads/:uid already returns customer), not from a user-chosen search — so “viewing another customer’s data” is structurally impossible. PDPA-wise, staff only ever see data for the person they are actively serving.
