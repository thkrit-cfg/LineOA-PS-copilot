Personal Shopper Hub — Full App Wireframe

Personal Shopper is the name of our LINE OA sales channel. Two audiences, two surfaces: the Chat Page (store staff, mobile-first) and the Admin Portal (HQ support, desktop) — plus an internal support workbench. Customers do not use this product: they stay in their LINE chat (Flex cards, promo codes, tel: links). The old LIFF customer app is out of scope. Grayscale wireframe — layout and interaction only.

Customer touchpoints — inside LINE, no app

customer's LINE chat · no login · no LIFF

Decision (2026-09-19): the customer does not use this product. The Personal Shopper channel lives entirely inside the customer's LINE chat. The customer receives Flex cards (product recs, promo codes), can tap a tel: deep-link to call the personal shopper, and every touchpoint is logged to the journey log on the staff side. The old LIFF app (The 1 card, coupons, staff copilot) is out of scope.

Key flows

How the surfaces connect. Every flow ends in a LINE message to the customer or a data-lake write.

F1Customer asks about stock → staff replies with AI assist
Customer LINE msg → webhook (userId)→ Staff Inbox thread list (priority sort)→ Thread detail: intent chip + CRM strip→ ✦ AI draft (answer-shaped)→ Staff edits / sends→ Reply delivered via LINE
F2Unlinked customer → CRM identity resolution
Thread shows amber "not linked"→ Staff taps Link CRM→ CRM drawer: search phone / name / The 1→ Profile expands → Set as Active Customer→ Thread now shows CRM context + copilot picks
F3HQ creates promo → staff offers it → customer claims
Admin Promotions: New (code, window, tiers)→ Live in staff inbox "on-going promos" strip→ Staff taps promo → inserts into reply→ Customer sees promo Flex card in chat→ Code used at checkout (The 1 card / POS)
F4In-store upsell: staff copilot → Flex card in chat
Customer chats with OA (in store)→ Staff opens thread: CRM strip + AI recs→ AI recs (recommendationEngine, confidence)→ Staff taps Send to LINE→ Flex card in customer chat → tap → order
F5Win-back campaign: rule → simulation → broadcast
Segmentation: new rule (inactivity + spend)→ Live evaluation: matches + revenue vs LINE cost→ Run trigger simulation→ Thai push + promo code → LINE · logged to push log
F6Staff question → HQ ticket → answer
Staff raises ticket (from a thread)→ Admin Tickets: open (branch + thread linked)→ HQ answers→ Mark resolved · KPI "open tickets" drops
